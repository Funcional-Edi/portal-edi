## O que aprendi

- **Ler o código antes de prometer uma regra.** "A requisição nova não vai
  automática para o cliente" parecia simples. Mas o `syncSchema` sobrescreve
  `schema.json`, e a tela `/docs/api` lê o schema inteiro. Reaproveitar o sync
  do jeito que está publicaria a requisição sem aprovação.
- **Estado operacional não é conteúdo.** O registro do Radar muda toda semana e
  não precisa de aprovação. Se passasse pela fila da qualidade, ela ficaria
  lotada. Por isso o estado vai para uma branch própria, fora de `main`.
- **Credencial e agendador precisam morar no mesmo lugar.** A senha do gateway
  fica cifrada em disco no portal. O agendador do GitHub só "toca a campainha":
  quem lê o gateway é o portal.
- **Histórico interno em arquivo separado.** Colocar dentro de `manual.json`
  arriscaria vazar para as telas do distribuidor.
