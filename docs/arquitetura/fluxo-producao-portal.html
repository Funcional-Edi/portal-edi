Quem entra e o que cada um vê

Todo mundo entra pelo mesmo login. O papel depende de estar ou não na lista.

Admin master

Acesso a tudo. Aprova, publica e escolhe a versão.

Editor EDI

Acesso às edições. Altera e envia. Não publica.

Visualizador

Todo login do SSO que não está liberado como admin master nem como editor EDI. Vê só a versão do manual.

Duas versões. O visualizador só vê uma.

A versão do manual é o que muda o desenvolvimento do distribuidor. A versão interna fica só com o time EDI.

Versão do manual

Quem vê: o visualizador

  • Requisição nova
  • Campo ou regra que muda a integração
  • O número da versão sobe, por exemplo de 1.2 para 1.3
Versão interna

Quem vê: só o time EDI

  • Correção de texto
  • Exemplo ou ajuste que não muda a integração
  • O número que o visualizador vê continua o mesmo

Como uma alteração chega lá

Quatro passos. A escolha acontece só no final.

  1. 1
    O editor muda o conteúdo Manual, gateway, catálogo ou subproduto.
  2. 2
    O visualizador ainda não vê A alteração fica guardada até o admin aprovar.
  3. 3
    O admin aprova Quem enviou não aprova a própria alteração. Se devolver, o editor ajusta e envia de novo.
  4. 4
    O admin responde uma pergunta Isso muda o desenvolvimento do distribuidor?
    Sim → versão do manualO visualizador passa a ver
    Não → versão internaSó o time EDI vê

Versões anteriores ficam salvas

Nada que já foi aprovado some. Restaurar não apaga o histórico: abre uma proposta nova e o admin aprova de novo.

  1. 1
    A versão do manual fica no histórico público O visualizador vê a data, o que mudou e o número. Não vê quem fez.
  2. 2
    A versão interna fica só na área do EDI O visualizador não vê esse histórico.
  3. 3
    O admin escolhe “Restaurar esta versão” Abre uma proposta na mesma fila e só vale depois da aprovação. O histórico antigo permanece e a restauração entra como uma linha nova. Se for do manual, o visualizador vê uma versão nova. Se for interna, o número dele não muda.

O que se ganha

Autonomia do time EDI

O editor altera pela tela. Não depende de mudança de código nem de deploy.

Nada muda direto

Toda alteração espera o admin. Quem enviou não aprova a própria.

O distribuidor vê só o que lhe impacta

Versão interna não aparece para ele. Se a mudança mistura impacto e texto, vale a versão do manual.

Dá para voltar

No histórico, o admin escolhe “Restaurar esta versão”. Isso abre uma proposta na mesma fila e só vale depois da aprovação. O passado não é apagado: a restauração entra como uma linha nova.
