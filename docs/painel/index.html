O que é o Portal EDI

Portal modular do time EDI / Tecnologia: documentação viva (interna e externa), fluxogramas, homologação e automações com IA. Construído com fundação primeiro — esqueleto sólido (auth, segurança, arquitetura) antes de features.

Estado atual: MVP da migração da documentação viva concluído (Fases 0–10). Portal roda stateless (sem banco de dados) por decisão explícita — ver aba Cronograma.

Stack

Next.js 15 (App Router)
UI + BFF num só processo — não existe "back" e "front" separados.
TypeScript + Zod
Tipagem estática + validação de dados na borda (schemas).

Login SSO (contrato do portal legado) + RBAC por papel.

Sem banco
Stateless-first (ADR-0002); conteúdo em arquivos.

Regra de ouro da arquitetura

app → modules → core

core/ é a fundação (auth, config, db, ai, events) e não conhece modules/ nem app/. Módulos são contextos isolados que não se importam entre si — só conversam via core/events. Validado automaticamente por npm run arch; violação quebra o CI.

Comandos essenciais

npm run dev — sobe o portal em http://localhost:3002
npm run ci — typecheck → lint → arch → test → build (rodar antes de commitar)
npm run obsidian:watch — sincroniza notas do Obsidian em tempo real
npm run smoke:homolog — checklist automatizado de homologação

core/ — a fundação (sem regra de negócio)

core/auth

SSO, papéis (roles.ts), RBAC (module-access.ts), rate limit de login, sessão JWT.

core/security

Anti-SSRF em URLs de gateway, validação de Origin (CSRF), checagens de produção.

core/db

Gate de capacidades de dados — decide se um módulo pode ativar sem banco.

core/ai

Provedor de IA plugável, guardrails de segurança, orçamento mensal.

core/events

Única forma de comunicação entre módulos (pub/sub), evita acoplamento direto.

core/config

Leitura segura de variáveis de ambiente (env.ts) — nenhum módulo lê process.env direto.

core/metrics

Métricas in-memory do playground GraphQL (voláteis por processo).

core/search

Índice Fuse.js para a busca global (Ctrl+K).

core/ui

Casca compartilhada: AppShell, Badge, SessionActions.

core/errors

Tratamento de erro padronizado entre camadas.

modules/ — contextos de negócio

living-docs-externa ativo

Manual de integração para clientes: /manual, playground GraphQL, export Postman/Insomnia/PDF.

manuais-internos ativo

Guias internos do time EDI em /interno (só admin).

fluxogramas ativo

Fluxogramas BPMN em /fluxogramas, acessível a clientes e time.

Cada módulo segue a convenção: module.ts (contrato), schema/ (Zod), repository/ (acesso a dado), services/ (regra de negócio), ui/ (opcional). Registro central em modules/registry.ts.

Regra principal (regra Cursor seguranca-dados.mdc)

Ao identificar risco de segurança, vazamento de dados ou violação de compliance, a IA deve:

  1. Parar — não implementar, commitar ou prosseguir com a ação arriscada.
  2. Alertar — explicar o que está errado e o impacto.
  3. Orientar — indicar a forma correta, com referência ao arquivo/padrão do projeto.
